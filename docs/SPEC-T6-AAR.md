## 1. 요약

대표 링크가 특정 프리셋일 때, 태그에 **AAR(Android Application Record)** 1개를 함께 기록해
안드로이드에서 브라우저를 거치지 않고 해당 앱이 바로 열리게 합니다.
**프리셋별 기본값**을 앱이 정하고, **사용자가 뒤집을 수 있으며**, 켜는 시점에 손해를 먼저 고지합니다.

**6개 프리셋 전부 토글 활성.** 패키지명을 6종 모두 1차 출처로 확인했습니다(§4).
**초기값은 6개 전부 꺼짐.** 관측 근거가 있는 인스타그램도 예외 없이 꺼짐에서 시작합니다 —
앱이 미리 판단하지 않고, 켤지 말지는 매번 사용자가 본인 네트워킹 상황에 맞춰 정합니다.

스위치는 링크 행이 아니라 **목록 맨 위에 고정된 독립 패널**에 있습니다. 대표 링크는 항상
목록 1번 자리로 이동하므로(T2a), 패널이 그 자리 위에 고정돼 있으면 대표가 바뀔 때마다
패널 내용(`현재 대표: OO`)만 새로 그리면 됩니다. 대표가 바뀌면 체크박스는 **자동으로 꺼짐**(T6i).

## 2. 배경 — 왜 지금인가

**관측된 문제 (사용자 보고):**

- 대상: 대학생 네트워킹. 명함 대신 NFC 태그로 인스타그램 계정을 교환.
- 이 집단은 인스타그램 설치율이 **사실상 전원**이고, 네트워킹 자체가 인스타그램에서 일어남.
- **구형 안드로이드**에서 태그를 찍으면 → 외부 브라우저가 먼저 열림 → 그 다음 앱으로 이동.
- 결과: **상당한 불편감과 낮은 신뢰도.** 태그가 제대로 동작하지 않는 것처럼 보임.

**이것이 앞선 검토를 뒤집은 지점입니다.**
`PREMORTEM-AAR.md` §11.5에서 물었던 *"치명적이라는 걸 어떻게 아셨습니까"* 의 답이
**추정이 아니라 실사용 관측**이었습니다. 코끼리 1·2(미측정 동기)가 해소됩니다.

**이전 검토에서 제기했던 반대와 그 처리:**

| 반대 | 처리 |
|---|---|
| 용량 40 B가 보이지 않게 소모됨 | ✅ 게이지에 별도 항목으로 노출 (§5.3) |
| 이득이 있는지 미측정 | ✅ 실사용 관측으로 해소 |
| 오판 시 앱스토어로 감 (비대칭 비용) | ✅ **판단 주체를 사용자에게 넘김.** 자기 네트워킹 상황(구형 안드로이드 리스크 포함)을 아는 건 사용자이지 앱이 아님. 앱은 **초기값**만 제시(§4), 최종 판단은 켤 때마다 사용자가 함 |
| 동의자 ≠ 피해자 | 사용자 판단 + 고지로 이전. **제품 결정:** 도구형 앱이므로 선택지 제공까지가 앱의 역할 |
| U5(lock bit) 선례와의 일관성 | lock bit은 **되돌릴 수 없음**, AAR은 **태그를 다시 쓰면 사라짐**. 가역성이 다르므로 U5와 같은 처리를 하지 않습니다 (§3 T6h) |

## 3. T6 결정문 — `DECISIONS.md` STAGE 2, T5 다음에 삽입

| ID | 결정 |
|---|---|
| **T6** | **AAR 레코드 = 지원.** 대표 링크의 프리셋에 연동된 **옵션 1개**. 프리셋별 기본값을 앱이 정하고 사용자가 재정의 |
| **T6a** | **AAR은 태그당 최대 1개.** 대표 링크(T2a)의 프리셋 패키지와 동기화. **대표가 바뀌면 AAR도 따라 바뀜** |
| **T6b** | **직렬화 위치 = 마지막 레코드.** 첫 레코드는 대표 URI(T2b)를 유지 — 안드로이드는 첫 레코드로 MIME/URI를 판별하므로 AAR을 첫 레코드에 두지 않습니다 |
| **T6c** | **런타임 상태는 on/off 1개뿐**(현재 대표 기준), 초기값 꺼짐. 프리셋별로 따로 저장하지 않음 — 대표가 바뀌면 리셋되는 T6i가 이유. 켤지는 전적으로 사용자의 네트워킹 상황 판단 — 앱은 초기값에 어떤 편향도 주지 않음 |
| **T6d** | **대표가 「기타」면 옵션 비활성.** 임의 URL은 패키지명을 도출할 수 없음 — 이것만은 판단이 아니라 데이터 한계 |
| **T6e** | **패키지명 1차 출처 확정을 토글 활성의 전제로 유지.** 6개 프리셋 전원 확인 완료(§4) → 전부 활성. 향후 프리셋 추가 시에도 이 게이트는 유지 |
| **T6f** | **켜는 시점에 고지 시트 노출** (§5.2). 손해를 먼저 씀. 기본 포커스는 「켜지 않음」. **세션 정의:** 같은 링크 목록으로 여러 태그에 연달아 기록하는 동안(U7)은 최초 1회만 고지, 홈으로 나가면 세션 종료. **단, 사용자가 체크박스를 수동으로 껐다 다시 켜면** 자동 이어쓰기가 아니라 새로 켜는 행위이므로 **매번 다시 고지** |
| **T6g** | **iOS에서도 노출하되 「안드로이드에서만 적용」을 명시.** 아이폰 사용자가 안드로이드 상대에게 태그를 건네는 경우가 실제 사용 시나리오이므로 숨기지 않습니다 |
| **T6h** | **가역.** 태그를 다시 쓰면(U8 전체 재쓰기) AAR도 제거됨. U5(lock bit)와 달리 되돌릴 수 있으므로 노출합니다 |
| **T6i** | **대표 링크를 바꾸면 체크박스는 자동으로 꺼짐.** 이전 대표에 대해 본 고지가 새 대표에게는 적용되지 않으므로, 다시 켜려면 새 대표에 대한 고지를 새로 봐야 함 |

## 4. 프리셋별 패키지명과 초기값

**6종 전부 1차 출처로 확인.** 출처가 없어 토글을 막았던 T6e 게이트는 해소됐습니다 —
남은 건 install-rate 판단이 아니라 **"켤지 말지"는 사용자 몫**이라는 원칙 그 자체입니다(§3 T6c).

| 프리셋 | 패키지명 | 출처 | 초기값 |
|---|---|---|---|
| Instagram | `com.instagram.android` | Meta 개발자 문서 (Sharing to Reels) | 꺼짐 |
| GitHub | `com.github.android` | Play Store 리스팅 (`id=` 파라미터, 리스팅명 "GitHub") | 꺼짐 |
| LinkedIn | `com.linkedin.android` | Play Store 리스팅 (리스팅명 "LinkedIn: Community & Network") | 꺼짐 |
| X | `com.twitter.android` | Play Store 리스팅 (리스팅명 "X") | 꺼짐 |
| TikTok | `com.zhiliaoapp.musically` | TikTok 개발자 문서 (Share Kit, `TIKTOK_M_PACKAGE`) | 꺼짐 |
| YouTube | `com.google.android.youtube` | Google 개발자 문서 (YouTube Android Live) | 꺼짐 |
| **기타** | — 도출 불가 | — | **토글 자체가 없음** (T6d) |

> **왜 전부 꺼짐인가.** 인스타그램은 관측된 실사용 근거가 있지만, 그걸로도 앱이 대신
> 켜주지는 않습니다. 판단 주체를 사용자에게 넘긴다는 원칙(T6c)을 지키려면 앱이 특정
> 프리셋에 유리한 초기값을 주는 것 자체가 그 원칙과 어긋납니다. 6개 전부 같은 출발선에서
> 시작하고, 최종 결정은 언제나 §5.2 고지 시트에서 사용자가 합니다.

> **패키지명 신뢰도 — 출시 전 재확인 권장.** Instagram·TikTok·YouTube는 각 서비스의 공식
> 개발자 문서에서 확인했지만, **GitHub·LinkedIn·X는 Play Store 리스팅 제목으로만 확인**했습니다.
> 지금은 전부 초기값 꺼짐이라 아무것도 자동으로 태그에 기록되지 않지만, 이 세 프리셋을
> 실제로 태그에 쓰기 전에는 각 서비스의 공식 딥링크·SDK 문서로 한 번 더 확인해야 합니다
> (`VERIFICATION.md` §5).

> **TikTok 참고:** 개발자 문서상 패키지가 2개입니다(`com.zhiliaoapp.musically` = 글로벌판,
> `com.ss.android.ugc.trill` = 다른 리전 빌드). 글로벌 서비스 프리셋 기준(F1)이므로 전자를 채택합니다.

**초기값을 조정하는 경우 (기록용):** 특정 프리셋에서 *"앱스토어가 떴다"* 는 보고가 들어오면
그 프리셋은 계속 꺼짐으로 둡니다. 프리셋 초기값은 앱 업데이트로 수정 가능합니다(F4) —
**토글의 존재 자체는 이미 사용자 손에 있으므로, 초기값 변경은 힌트를 바꾸는 것일 뿐입니다.**

## 5. 화면 사양

### 5.1 스위치 위치

**링크 목록 맨 위, 고정된 독립 패널.** 어떤 링크 행에도 붙지 않습니다. 대표는 항상
목록 1번 자리로 이동하므로(T2a), 패널을 그 위에 고정해두면 대표가 바뀔 때 패널
내용만 다시 그리면 됩니다. 고급 설정에 숨기지 않습니다.

```
용량 게이지  87 / 137 B
────────────────────────────────────────
┌──────────────────────────────────────┐
│ 현재 대표: Instagram                   │
│ 안드로이드에서 앱 바로 열기       [ ]  │
└──────────────────────────────────────┘
────────────────────────────────────────
① Instagram (대표)   instagram.com/hong/
② GitHub             github.com/hong
```

### 5.2 켜는 시점의 고지 시트 (T6f)

**손해를 먼저 씁니다.** 끄는 방향에는 시트를 띄우지 않습니다.

```
인스타그램 앱으로 바로 열기

⚠️  인스타그램이 설치되지 않은 기기에서는
    프로필 대신 앱 설치 화면이 열립니다.
    링크는 열리지 않습니다.

이 태그를 찍는 안드로이드 기기에서 브라우저를
거치지 않고 인스타그램 앱이 바로 열립니다.

·  아이폰에서는 이 설정과 무관하게 동작합니다
·  태그 용량 40 B를 사용합니다
·  태그를 다시 쓰면 해제됩니다

        [ 켜지 않음 ]      [ 켜기 ]
```

- 기본 포커스 = **「켜지 않음」**
- 문구를 부드럽게 다듬지 않습니다. *"드물게"*, *"대부분의 경우"* 같은 완화어를 넣는 순간
  고지가 유도로 바뀌고 책임 이전이 성립하지 않습니다.
- **고지가 뜨는 시점 (T6f):** 체크박스를 켜는 행위 자체에 걸립니다.
  - U7 연속 쓰기(같은 링크 목록으로 여러 태그에 이어서 기록)로 자동 반복될 때는 **최초 1회만.**
    홈으로 나가면 세션이 끝나 다음에 켤 때 다시 뜹니다.
  - 사용자가 껐다가 **직접** 다시 켜면 그건 이어쓰기가 아니라 새로 켜는 행위이므로 **다시 뜹니다.**
  - 대표 링크가 바뀌면 체크박스가 자동으로 꺼지므로(T6i) 다시 켜려는 순간 새 고지가 뜹니다.

### 5.3 용량 게이지 (U4b 연장)

AAR을 **별도 항목으로** 보여줍니다. 합계에만 반영하고 항목을 숨기면 U4b의 취지가 깨집니다.

```
링크 5개                87 B
앱 바로 열기 설정        40 B
────────────────────────────
                   127 / 137 B
[████████████████████░░]
```

- 켜고 끌 때 **게이지가 즉시 움직여야** 합니다 — 비용이 보이는 유일한 지점입니다.
- 초과하면 U4c대로 저장 차단. **이때 안내는 "설정을 끄면 40 B가 생깁니다"** 를 함께 제시.

### 5.4 태그 읽기 화면 표시

**5.4a — ① 읽기 화면 (`Read.html`).** 대표 배지(*"탭하면 이 링크가 열립니다"*) 옆에 1줄 추가:

```
앱 바로 열기    켜짐 · 인스타그램
```

**5.4b — ③ 태그 상태 확인 (`TagStatus.html`, U1e/S1 연장).** 동일한 표시를 진단 항목으로도 추가.
③은 "이 태그 상태를 전부 보여주는" 화면이므로 AAR 유무도 그 상태의 일부입니다.

두 화면 모두 AAR이 없으면 그 줄을 표시하지 않습니다.

### 5.5 완료 화면 (`Done.html`)

AAR을 켜고 저장했을 때만 1줄:

```
✓ 저장 완료
  안드로이드에서 인스타그램 앱으로 바로 열립니다
```

## 6. 기술 사양

```java
// 마지막 레코드로 추가 (T6b)
NdefRecord aar = NdefRecord.createApplicationRecord("com.instagram.android");
```

**안드로이드 디스패치 동작** (developer.android.com/develop/connectivity/nfc/nfc):

1. 인텐트 필터로 액티비티를 먼저 찾는다. 그 액티비티가 AAR과도 일치하면 실행한다.
2. 일치하지 않거나 / 후보가 여럿이거나 / 처리할 액티비티가 없으면 → **AAR이 지정한 앱을 실행한다.**
3. **앱이 기기에 없으면 → Google Play가 열린다.** ← 이 옵션의 손해가 발생하는 지점
4. 안드로이드는 NDEF 메시지 **전체**에서 AAR을 찾는다. 단, **첫 레코드로 쓰지 말 것**
   (AAR이 유일한 레코드인 경우 제외) — 시스템이 첫 레코드로 MIME/URI를 판별하기 때문.

**레코드 크기:** 헤더 3 + 타입 `android.com:pkg` 15 + `com.instagram.android` 22 = **40 B**

| 1 | 6개 프리셋 패키지명 전원 | ✅ **확인** | §4 표 — Meta/TikTok/Google 개발자 문서 3건 + Play Store 리스팅 3건 |
| 2 | **iOS Core NFC가 TNF_EXTERNAL 레코드를 쓸 수 있는가** | ⚠️ **T6g의 전제** | `NFCTypeNameFormat.nfcExternal`이 있으나 실기 확인 필요. 불가로 판명되면 T6g를 「iOS 숨김」으로 되돌림 |
| 3 | Android 16의 `ACTION_VIEW` 전환에서 AAR 우선순위 | ⚠️ 미문서화 | 이 옵션이 **조용히 동작을 멈출 수 있는 유일한 경로.** 실기 확인 대상 |
| 4 | GitHub·LinkedIn·X 패키지명을 공식 딥링크/SDK 문서로 재확인 | ⚠️ **쓰기 전 필수** | 현재는 Play Store 리스팅 제목으로만 확인(§4). 전부 초기값 꺼짐이라 출시는 막지 않지만, 이 세 프리셋을 실제로 켜서 태그에 쓰기 전엔 재확인 |
| 5 | NTAG213 실측 137 B | 기존 항목 | `VERIFICATION.md` §5에 이미 있음 |

**2·3·4번은 출시를 막지 않습니다.** 2번은 실패해도 안드로이드 사용자에게는 정상 동작하고,
3번은 실패해도 링크는 열립니다(AAR이 무시될 뿐). 4번은 해당 프리셋을 실제로 켜기 전까지는
발생하지 않는 리스크입니다.
